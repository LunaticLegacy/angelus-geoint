# GEOINT 系统连接器使用指南

## 核心概念：连接器 = 大模型钥匙

在 Angelus GEOINT 系统中，**连接器（Connector）只有一个作用：配置大语言模型（LLM）的访问方式**。

它**不**包含：
- 地图服务 Key（天地图、Google Maps 等）→ 由系统全局管理
- 地理数据存储路径 → 由 Session 自动管理
- 分析工具参数 → 由 Agent 运行时决定

---

## 一、配置连接器（一次性）

### 步骤

1. 打开 Angelus GEOINT 工作台
2. 点击左侧边栏底部的 **⚙️ 设置**
3. 选择 **连接器** 标签页
4. 点击 **+ 新建连接器**
5. 填写以下字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| **名称** | 给人看的标签，方便识别 | `DeepSeek-V3`、`Kimi-K3`、`本地 Ollama` |
| **提供商** | LLMFetcher 支持的驱动类型 | `deepseek`、`kimi`、`openai`、`ollama` |
| **模型** | 具体模型名称 | `deepseek-chat`、`kimi-k3`、`gpt-4o` |
| **API 地址** | 可选，自定义端点 | `https://api.deepseek.com` 或留空用默认 |
| **API 密钥** | 你的 LLM 服务商密钥 | `sk-xxxxxxxx` |

6. 点击 **保存**

### 常见配置示例

#### 云端模型（推荐新手）

```json
{
  "name": "DeepSeek-V3",
  "provider": "deepseek",
  "model": "deepseek-chat",
  "api_url": "",
  "api_key": "sk-你的密钥"
}
```

#### 本地模型（离线/隐私场景）

```json
{
  "name": "本地 Llama3",
  "provider": "ollama",
  "model": "llama3.1:8b",
  "api_url": "http://127.0.0.1:11434",
  "api_key": ""
}
```

> **注意**：本地模型（Ollama）通常不需要 API Key，留空即可。

## 二、创建 Session（选择连接器）

### 步骤

1. 点击左侧边栏的 **+ 新建调查会话**
2. 填写会话名称，如 `大荔县 2024 年干旱分析`
3. **关键步骤**：在 **连接器** 下拉菜单中选择刚才配置的连接器
4. （可选）上传区域边界文件（Shapefile/GeoJSON）
5. 点击 **创建**

### Session 与连接器的关系

```
连接器（全局）                    Session（一次调查）
┌─────────────────┐            ┌─────────────────────────┐
│ DeepSeek-V3     │◄───────────│ 大荔县干旱分析           │
│ provider: deepseek│  绑定    │ connector_id: conn_xxx  │
│ model: deepseek-chat│        │ 边界: 大荔县.shp         │
│ api_key: sk-*** │            │ 数据: 降水、NDVI...      │
└─────────────────┘            └─────────────────────────┘
```

- **连接器是全局的**：配置一次，所有 Session 可用
- **Session 绑定连接器**：创建时选择，运行时可切换
- **切换连接器**：在 Session 设置里改 `connector_id`，数据不丢失

---

## 三、运行时的连接器使用

### 首次运行

1. 在 Session 页面点击 **运行**
2. 系统自动执行：
   - 从 Session 配置读取 `connector_id`
   - 从连接器存储读取 `api_key`
   - 构建 `LLMBackendConfig`
   - 初始化 LLMFetcher
   - 创建 Coordinator Agent
3. 开始对话

### 切换连接器（换脑）

1. 在 Session 页面点击 **⚙️ 设置** → **运行配置**
2. 修改 **连接器** 下拉菜单
3. 保存
4. 下次运行时自动使用新连接器

> **重要**：切换连接器只改变"大脑"，Session 里的地理数据、地图状态、历史对话全部保留。

## 四、地理数据服务（不需要连接器）

以下服务由系统全局管理，**不通过连接器配置**：

| 服务 | 配置位置 | 说明 |
|---|---|---|
| 天地图底图 | `settings.json` 或环境变量 | 全局 `TIANDITU_KEY` |
| Google Maps | `settings.json` 或环境变量 | 全局 `GOOGLE_MAPS_KEY` |
| 公开数据集下载 | 无需配置 | Agent 自动识别公开 URL |
| 本地 Shapefile/GeoJSON | Session 上传 | 用户直接上传 |

### 配置地图服务（管理员/开发者）

如果你需要修改地图服务，编辑系统设置文件：

```json
// .angelus-state/settings/geoint.json
{
  "basemaps": {
    "tianditu": {
      "api_key": "你的天地图Key",
      "enabled": true
    },
    "osm": {
      "enabled": true
    }
  }
}
```

## 五、常见问题

### Q1: 我可以给不同的 Session 用不同的模型吗？

**可以。** 创建多个连接器，每个 Session 绑定不同的连接器即可。

例如：
- Session A（快速筛查）→ 绑定 `DeepSeek-V3`（便宜快速）
- Session B（深度报告）→ 绑定 `Kimi-K3`（长文本强）

### Q2: 切换连接器后，之前的分析结果会丢失吗？

**不会。** 连接器只影响后续的 LLM 调用。Session 里的：
- 上传的地理数据
- 已完成的派生计算
- 地图图层状态
- 历史对话记录

全部保留。

### Q3: 本地模型和云端模型可以混用吗？

**可以。** 配置两个连接器：
- `本地 Ollama`：处理敏感/离线数据
- `云端 DeepSeek`：处理需要强推理的任务

在同一个 Session 里随时切换。

### Q4: 为什么连接器里没有地图 Key 的配置？

**设计决策。** 地图服务是系统级资源，不应该随 LLM 连接器切换而变化。如果你的组织需要自定义地图服务，请联系管理员修改全局配置。
