# 阡陌问旱：农业干旱证据调查智能体——参赛方案

本方案依据同目录项目包中的《提交材料.docx》制定。文档定位为参赛策划及作品说明书写作底稿，不替代签字盖章后的正式提交件。

## 1. 定位与选题

- 建议作品名：阡陌问旱：农业干旱证据调查智能体（小于30字符）。
- 建议赛道：AI+农林行业应用赛。
- 服务对象：农业遥感研究人员、农技人员、农业相关专业师生。
- 具体问题：针对指定区域和时段，汇集降水、植被与农地数据，计算可核验的异常指标，帮助使用者判断是否存在值得进一步核查的农业干旱信号。
- 产品目标：用户选择区域和时间、提出问题，即可获得地图、数据摘要和带来源的调查报告，并能追溯计算过程。
- 系统角色：辅助调查与研究；作物损失、灌溉处方及灾害等级需要相应地面观测和专业验证，不作为首版承诺。

### 创意描述（100字以内）

面向农业干旱调查，将自然语言提问、遥感数据分析与地图证据联动结合，形成可追溯、可复核的调查报告。系统区分数据事实、分析推断与信息缺失，帮助农技人员和研究者快速定位异常区域并开展核查。

## 2. 核心案例与演示

主案例限定为陕西省内一个县域（优先选择已有数据覆盖且可获取农业用地范围的县），研究一个完整生长季。县域、年份和比较基准在数据检查后固定；不得将单点NDVI代表整个县域，不得将六年样本称为长期气候基准。

示例问题：“请调查该县选定生长季的植被与降水异常，标出需要重点核查的农业区域，并说明证据与局限。”

演示操作：

1. 打开已配置好的示例项目，看到县域范围和数据覆盖清单。
2. 选择调查时段并发送问题，显示简短调查步骤和执行进度。
3. 加载降水、植被异常及农业用地相关图层，查看区域统计与有效像元比例。
4. 点击报告中的证据，定位对应图层或数据记录。
5. 展示事实、推断、不确定性、缺失数据与建议补充的调查报告。
6. 恢复会话，展示已归档的结果、参数和来源。

建议录制约4分钟演示视频；这是建议时长，模板未规定视频时长。可重放已归档案例，并明确标识“历史案例”；现场联网重新运行作为附加演示，不冒充离线推理。

## 3. 技术方案

交互流程图（正式说明书绘制为编号图片）：

```text
区域与时段选择 → 自然语言调查问题 → 数据可用性检查
                                      ↓
                             调查计划与授权工具调用
                                      ↓
                          数据质量检查、对齐与空间统计
                                      ↓
                           数据产物和来源、参数归档
                                      ↓
                         地图展示 ↔ 带证据的调查报告
                                      ↓
                                人工复核与导出
```

后端分工：Angelus负责会话、运行控制、工具调用和产物归档；GEOINT负责会话绑定资产、地理处理、地图文档和分析结果。前端按工作区、地图、调查聊天、图层检查器和设置组件拆分。工具卡通过通用输入输出和执行状态呈现，不针对具体工具硬编码。

数据处理方案：

- 固定版本的行政区边界、农业用地掩膜、降水和植被数据形成案例数据清单，记录来源、获取日期、覆盖范围、时间分辨率与校验值。
- 对栅格完成坐标、分辨率、时间窗口和NoData处理，统计有效覆盖；缺失时直接显示缺失。
- 首版采用透明的同期对比统计；具体异常计算公式、基准年份和样本量写入报告，不以LLM生成的数字代替计算结果。
- 长期序列及方法验证完成前，不将简单偏差包装为SPI/SPEI，也不宣称已实现干旱预测或灾损评估。
- 分析结果保留输入资产、算法/工具版本、参数、输出与证据标识；报告数字能回到对应统计记录。
- LLM承担任务拆解、工具编排和有依据的报告组织，空间数值计算由确定性处理程序承担。

可主张的特色：面向农林调查的自然语言入口；地图、数据与报告之间的证据关联；明确呈现不确定性与缺失；可恢复的调查过程。以上应称为作品设计特色，是否具有学术或同类产品创新性需要另行比较和论证。

## 4. 当前基础与参赛前交付门槛

现有项目具备Angelus运行框架、GEOINT资产目录和地图呈现模块，以及OpenLayers地图、调查聊天和可拖拽面板的前端代码。此前构建通过不能证明真实案例已经端到端完成。

| 项目 | 参赛前必须提供的证明 |
|---|---|
| 数据可靠性 | 一份固定案例数据清单，实际覆盖范围和缺失说明 |
| 数值分析 | 至少一个完整县域案例的真实区域统计及独立复核结果 |
| 地图呈现 | 与统计结果一致的真实图层；移除与数据无关的静态风险图例 |
| 证据报告 | 图表、数字、数据来源逐项可追溯；无来源内容标注为推断或缺失 |
| 交互完整性 | 选择项目、运行、看结果、恢复会话的浏览器实测记录 |
| 稳定性 | 刷新、切换会话、断网、停止任务、无数据时的明确反馈 |
| 可交付性 | 安装/启动说明、固定依赖、演示数据、示例报告、演示视频 |

优先修复真实分析闭环与聊天恢复、滚动、重连等稳定性问题；完成后再做默认界面简化。默认只突出地图、调查和数据入口，连接器与高级上下文放入设置，保留高级面板功能。

## 5. 验证与应用价值

应用价值围绕“减少跨工具查找与整理成本、提升证据可复核性”展开，暂不填写未经测量的节水比例、增产收益或准确率。

安排以下实验，并在正式说明书中填入实际结果：

1. 数值复核：用独立GIS流程复核同一输入下的区域统计；记录误差、重采样和NoData口径。
2. 报告核验：逐条检查报告数字和引用，统计可追溯比例及错误数量。
3. 对照任务：以同一问题比较人工跨工具流程、仅LLM回答和本系统流程；记录完成时间、有效证据数量、计算与引用错误。结果不得提前写成性能提升结论。
4. 操作可用性：邀请农林相关用户完成固定任务，记录完成率、求助次数和主要困惑。
5. 异常场景：覆盖资产缺失、时间不匹配、工具失败、会话切换和服务重启；检查既有结果不会串会话或被误报为新结果。

农业价值以县域调查、农业遥感教学和灾情资料辅助整理为首批场景。推广阶段再评估其他县域、其他作物与其他灾害类型。
